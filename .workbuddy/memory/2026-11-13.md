## 人生RPG 加「打卡换娱乐额度」功能

**背景**：用户原本是单文件 `index.html`（localStorage 键 `lifeRPG.v1`），用 GitHub 开源工具打包成 APK。小米手机，**有 root（Magisk）**。

**决策链**（与用户逐条确认过）：
1. 路线：Capacitor 壳 + 原生代码（不重写 HTML）
2. 前台识别：无障碍服务（事件驱动）识别，root 执行动作
3. 管控动作：`su -c am force-stop <pkg>`（不选 `pm disable-user`，太狠）
4. 额度规则：每次打卡 +30 分钟，**累加不过期**，用户明确拒绝"单日消费上限"
5. 奖励与受管应用**全部可配置**，不硬编码抖音（用户还没想好奖励对应关系）
6. UI 命名：卡片叫「**娱乐额度**」，不叫「抖音额度」
7. 编译：GitHub Actions 云编译（本机无 JDK/Android SDK）

**结论**：小米「屏幕使用时间」的应用限制无公开 API，root 下改私有数据库太脆弱，**不接**，自研。

## 工程结构（C:/Users/a1852/Desktop/ces）
- `www/index.html` 正式文件；`backup/index.html.2026-11-13.html` 原文件快照
- 根目录 `index.html` 是旧副本，已 gitignore
- `android/app/src/main/java/com/liferpg/control/` 下 **用 Java 不用 Kotlin**（避免引入 Kotlin Gradle 插件，减少 CI 编译失败面）
- appId `com.liferpg.control`，appName 人生RPG
- 原生桥不用 Capacitor 插件注册，而是 `MainActivity` 里 `webView.addJavascriptInterface(new NativeBridge(this), "RewardNative")` —— 比插件打包链路可靠得多

**原生类**：Wallet（wallet.json 落盘）/ GuardService（前台服务计时）/ AppWatcher（无障碍）/ BlockOverlay（TYPE_ACCESSIBILITY_OVERLAY，无悬浮窗权限也能用）/ RootShell / NativeBridge / BootReceiver

**前端**：`RewardBridge` IIFE，有 `window.RewardNative` 走原生，否则降级 localStorage 键 `lifeRPG.reward.v1`（方便浏览器预览）；`renderRewardCard()` 插在 `#skillSum` 后；`window.__androidBack()` 接管返回键

**坑**：Android 15+ 强制 edge-to-edge → `MainActivity` 把 insets 写进 CSS 变量 `--sat`/`--sab`

**验证**：jsdom 冒烟测试通过（打卡加额度、卡片渲染、设置弹窗、加应用、改时长、返回键）
